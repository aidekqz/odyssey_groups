# AGENTS.md

## Назначение

Этот репозиторий — локальный стенд для ручного тестирования [Odyssey](https://github.com/yandex/odyssey), в первую очередь экспериментов с группами ролей PostgreSQL и аутентификацией LDAP/IAM. Исходного кода и бинарного файла Odyssey здесь **нет**: клонируйте и собирайте их отдельно, как описано в `README.md`.

## Структура репозитория

- `configs/` — варианты конфигурации Odyssey:
  - `base.conf` — базовая конфигурация PostgreSQL и локальная административная консоль;
  - `config_group.conf` — тест маршрутизации по группам ролей PostgreSQL;
  - `config_ldap.conf` — тест LDAP-аутентификации;
  - `config_iam.conf` — тест аутентификации через IAM-прокси.
- `configs/ldap_conf/base.ldif` — начальные LDAP-записи.
- `scripts/` — подготовка окружения, контейнеры, вспомогательные команды подключения и smoke-тест.
- `scripts/init.sql` — роли, база данных и членство в группах PostgreSQL, используемые конфигурациями.
- `Makefile` — короткие команды для запуска PostgreSQL/LDAP и перезагрузки работающего Odyssey.

## Предварительные требования

- Bash, Docker, клиент PostgreSQL (`psql`) и `make`.
- Отдельно собранный клон Odyssey. Стандартный сценарий из README создаёт `./odyssey/build/sources/odyssey`; бинарный файл можно скопировать в `./odyssey_bin`.
- Доступ текущего пользователя к Docker. Скрипт `scripts/prepare_dep.sh` устанавливает зависимости в Debian/Ubuntu и добавляет пользователя в группу Docker; после этого потребуется заново войти в систему.

## Локальный сценарий работы

1. Запустите PostgreSQL:

   ```sh
   make run_postgres
   ```

   Команда пересоздаёт контейнер `postgres`, ждёт его готовности и применяет `scripts/init.sql`.

2. Для LDAP-сценариев также запустите LDAP:

   ```sh
   make run_ldap
   ```

   Команда пересоздаёт контейнер `openldap` и заполняет его данными из LDIF. Также она запускает `scripts/update_hosts_records.sh`, которому нужен `sudo` и который меняет запись `ldap.example.local` в `/etc/hosts` хоста.

3. Запустите Odyssey в foreground-режиме с проверяемой конфигурацией, например:

   ```sh
   ./odyssey_bin ./configs/config_group.conf
   ```

4. Проверьте прокси:

   ```sh
   ./scripts/test_group.sh
   ./scripts/connect_mon.sh
   ```

   Прокси слушает `127.0.0.1:6432`; PostgreSQL опубликован на `127.0.0.1:5432`; LDAP использует `127.0.0.1:389` и `:636`. Логи Odyssey пишутся в `/tmp/odyssey.log`.

5. После изменения конфигурации перезагрузите работающий `odyssey_bin` командой:

   ```sh
   make reload_odyssey
   ```

### TLS в базовой конфигурации

TLS обязателен для всех клиентских подключений в `configs/base.conf`. Перед
первым запуском Base Config выпустите локальный CA и сертификат сервера:

```sh
./scripts/issue_odyssey_tls_cert.sh
make run_postgres
make run_odyssey ODYSSEY_CONFIG=base.conf
```

Файлы появляются в `./certs/` и игнорируются Git. Скрипт `run_odyssey`
проверяет наличие `server.crt` и `server.key` для `base.conf`, затем монтирует
этот каталог в контейнер как `/etc/odyssey/certs` только для базовой
конфигурации. Не добавляйте TLS-параметры вручную: они уже заданы в
`configs/base.conf`.

Клиент должен доверять созданному CA:

```sh
psql "host=127.0.0.1 port=6432 dbname=db1 user=user1 sslmode=verify-ca sslrootcert=./certs/ca.crt"
```

Сертификат содержит SAN `localhost` и `127.0.0.1`, поэтому с этими именами
хоста можно применять и `sslmode=verify-full`.

Не путайте клиентский `sslmode=verify-ca` с режимом `tls "verify_ca"` в Odyssey: второй требует клиентский сертификат, подписанный доверенным CA.

## Рекомендации по изменениям

- Привязывайте варианты конфигурации к соответствующему сценарию. Если общее изменение относится ко всем сценариям, намеренно обновите каждую затронутую конфигурацию: это самостоятельные файлы, они не наследуют `base.conf`.
- Не меняйте подготовленные учётные записи PostgreSQL/LDAP, если одновременно не обновляются связанные конфигурации и smoke-тесты. Основные фикстуры: `user1` / `user1123`, `user2` / `654321` и группа PostgreSQL `group1`.
- Скрипты должны сохранять совместимость с Bash, использовать кавычки при подстановке переменных и завершаться при ошибках, когда это уместно (`set -e`/`set -x` уже применяются в подготовительных скриптах).
- Не коммитьте машинно-зависимые результаты, каталог/бинарный файл сборки Odyssey, состояние Docker-контейнеров или файлы из `/tmp`.

## Проверка

В этом стенде нет автоматизированного набора unit-тестов. Проверяйте изменения минимальным подходящим ручным сценарием:

- Синтаксис/поведение конфигурации: запустите Odyssey с изменённой конфигурацией и проверьте `/tmp/odyssey.log`.
- Сценарий PostgreSQL/групп: `make run_postgres`, запустите Odyssey с `configs/config_group.conf`, затем выполните `./scripts/test_group.sh`.
- LDAP-сценарий: `make run_postgres && make run_ldap`, запустите Odyssey с `configs/config_ldap.conf`, затем подключитесь к порту 6432 под `user2`.
- IAM-сценарий: перед использованием `configs/config_iam.conf` запустите требуемый поставщик сокета IAM-прокси; в этом репозитории его нет.

## Меры предосторожности

- Скрипты запуска контейнеров намеренно удаляют и пересоздают контейнеры с именами `postgres` и `openldap`. Перед запуском убедитесь, что эти имена не используются для другой работы.
- `scripts/update_hosts_records.sh` редактирует `/etc/hosts` через `sudo`; не запускайте его автоматически в несвязанных задачах.
- Учётные данные в репозитории — только тестовые фикстуры. Не используйте их вне этого локального стенда и не подменяйте реальными секретами.
